Recommended

A · Two tabs, like the main app

“★ My saved” and “All” as pill tabs. Same words and pattern users already know from the Edit clip modal.

How it works

  • Opens on My saved when the user has any, else on All. The last tab picked is remembered (localStorage).
  • Saved cards are bigger (3 per row) and preview their captions + sticker, so they read as “full looks”, not layouts.
  • First saved card is ＋ Save this edit; ⋯ on a card: rename, update with this edit, delete.
  • All is grouped by camera count (the lay-cam-groups fix for the two-camera finding).

Pros

  • One mental model across web app and editor.
  • Scales to 10+ saved without pushing presets off screen.

Cons

  • One click to switch; a returning user who wants a preset passes their saved tab first.

Option

B · Your templates on top, all below

No tabs. A horizontal row of saved templates, then the full layout grid. Both visible on open.

How it works

  • Row is sorted by last used; the row replaces “Recently used” and “Reuse a look”.
  • See all opens a saved-only view for users with many (rename / delete there).
  • Empty row collapses to one slim “＋ Save this edit as a template” line.

Pros

  • Zero clicks to reach either kind; closest to today’s layout, so the smallest probe risk.

Cons

  • Only ~3 saved visible without scrolling sideways.
  • Differs from the main app’s tabs.

Option

C · One grid, filter chips

Saved and Eklipse templates in one grid. Saved ones come first with a ★; chips filter by kind and camera count.

How it works

  • “★ Saved” is just a filter; camera chips also filter saved ones by their layout.
  • Selected chip is remembered for the next clip.

Pros

  • Single list to learn; filters answer “two cameras” directly.

Cons

  • Saved (full look) and Eklipse (layout only) apply differently but sit side by side; needs a clear badge and toast.
  • Busiest of the three.
